# app — 語灯 PWA (TypeScript/React)

オフラインファーストの辞書PWA。将来Capacitorでストア配布に移行するため、
Web標準から外れる実装(プラグイン前提の機能)は避けるか、抽象化して閉じ込める。

## 検索UX(最重要)

- 手本は物書堂系辞書アプリ: **読みのインクリメンタル・前方一致検索**が主役。
- 入力は必ず `shared/variants.json` で正規化してから照合する(旧字体・異体字を吸収)。
- 辞書DBは wa-sqlite / sql.js で読む。初回起動時にダウンロードし、以後オフラインで動く。
- 起動時の既定検索モード(文字・音声・カメラ)は設定で切り替え可能にする。音声・カメラは後続フェーズ。

## 勤行モード

- 差定はプレイリストモデル(仕様: `docs/saijo-spec.md`)。プリセットは複製→編集で、直接編集させない。
- ページ送りの主役は**片手持ち・親指タップ**: 画面下半分どこでも送り。1ページ以上飛ばない・
  画面端は無視・回転ロック。黒背景・大きめ文字・Wake Lockで消灯防止。
- **縦書き(経本)表示が既定**。ヘッダーのトグルで横書きに切り替えられる(実装済み)。
  縦書きは横書きと制約が逆転する(行数=画面の横幅、1行の長さ=画面の高さ)ため、
  文字サイズの段階もバッチ行数も向きごとに別ロジックで決める。
  表示の調整はunitのJSONではなく`src/lib/gongyo.ts`の汎用ロジックで行うこと。
- **現在地は式次第の項目番号**(「2 / 18」)。ここを押すと式次第の一覧(`GongyoOutline.tsx`)が
  開き、任意の偈文へ飛べる。一覧は`view`の状態機械には載せず**オーバーレイ**にする
  (`view`を切り替えるとimmersiveが解けてタブバーが出入りし、読誦中に画面が跳ねる)。
  読誦画面は全面がページ送りのタップ領域なので、重ねるUIのクリックは必ず
  `stopPropagation()`すること。
- **中断位置は`gotou:gongyo-progress`に保存**し、扉の「続きから」でのみ復帰する
  (`src/lib/gongyoProgress.ts`)。位置は`itemIndex`+項目内の相対ページで持つこと。
  絶対ページ番号は向き・カウンター設定で変わるため復元に使えない。
- 進捗バーの幅に`transition`は掛けない。`width: calc(var(--x) * 100%)`は
  カスタムプロパティだけが変わってもwidthの指定値が同じ式のままなので、
  Chromeはtransitionを張った状態では古い使用値に留まり帯が動かなくなる。
- テンポ式オートスクロールは合掌時向けオプション(v1.5、未着手)。

## デザイン基盤

- **色は必ず`src/index.css`冒頭のセマンティックトークン経由で参照する。**
  画面ごとに16進数を直書きしない(直書きが散在した結果、ライトモードで
  ボタンが黒い塊として浮き、ダークモードで区切り線が白すぎる状態になっていた)。
  ライト値を`:root`に、暗色値を`@media (prefers-color-scheme: dark)`に置く。
- コントラストはWCAG AA(本文4.5:1・大きい文字/UI部品3:1)を満たすこと。
  金・燈色は白背景で比が稼げないため、アクセントはライト`#8a5a00`(5.93:1)・
  ダーク`#e8b464`(11.14:1)と**モードごとに別値**にしている。色を足すときは
  必ず実測してから決める(目視で決めない)。
- **書体はUIクロムと本文で分ける**。タブ・ボタン・ラベル・設定は`--font-ui`
  (システムフォント)、辞書本文と勤行本文だけが`--font-content`(利用者が
  選んだ書体)。UI部品まで明朝で組むとアプリではなくWebページに見える。
- **勤行モードとその周辺(差定選択・編集)は端末がライトモードでも常に暗色。**
  `.shell-gongyo`等のスコープでトークンを上書きしているので、配下の部品は
  ライト/ダークを意識せずトークンを参照してよい。
- 操作部品のタップ領域は`--tap-min`(44pt)を下回らないこと。
- 主要なモード切り替えは画面下部のタブバー(片手持ちの親指が届く位置)。
  ただし**勤行の読誦中はタブバー・ナビバーを隠す**。「画面下半分どこでもタップで
  ページ送り」と衝突するため。扉画面は辞書へ戻る導線としてタブバーを残す。
- アイコンは`src/Icons.tsx`の自前インラインSVG(`currentColor`で描く)。
  外部アイコンライブラリは使わない。

## 典拠リンク(外部リンク)

- 辞書本文には浄土宗全書テキストDB・SAT大正蔵への**典拠リンクが元から埋まっている**
  (大辞典側のwikitextに存在する。詳細と調査結果は`docs/tenkyo-spec.md`)。
  `wikitextConvert.ts`がこれを`.external-link .tenkyo-link`に変換し、
  既知の2ホストのみ`http://`→`https://`へ引き上げる。判定条件は
  `factory/src/wikitext.py`と**厳密に一致させること**(両側に同じテストを置く)。
- **本文中の外部リンクは必ず新しいタブで開く**(`SearchMode.tsx`の`handleBodyClick`)。
  ホーム画面に追加したPWA(standalone)では、既定の遷移だとアプリ自身が外部サイトに
  置き換わり、ブラウザのUIも無いため戻る手段が無くなる。
- 外部サイトへ出る前に初回1回だけ確認を出す(`gotou:external-link-notice`)。
  オフライン時はトーストのみで遷移しない。**リンク先の存在確認等の事前リクエストは
  しない**(浄全DB・SATへの機械的アクセスをしない、という掟)。

## 逆引き典拠検索

- 検索欄のトグルで「見出し語で引く」と「一節から典拠をさがす」を切り替える
  (仕様・計測結果は`docs/tenkyo-spec.md` B節)。
- **日本語ではFTS5の`MATCH`が使えない。** 既定の`unicode61`トークナイザは句読点でしか
  区切らないため、句の途中の部分一致が常に0件になる。`entries_fts.body_text`への
  **LIKE全走査**を使う(本文は全体で4.4M文字しかなく約10ms)。
- **検索語から句読点を除去しないこと。** 本文側には句読点が残っているため、
  除去すると一致しなくなる(実測で再現率1%まで低下)。句読点で分割して
  句ごとに部分一致を取る(同条件で100%)。除去してよいのは浄全DBへ投げる語だけ。
- 外部サイトへ出る経路は`guardExternalNavigation()`に一本化してある。
  浄全DB検索はPOST送信で`window.open`を通らないため、関門を素通りさせないこと。
  アプリ内表示(iframe)も同じ関門を通す(文面だけ`externalEmbedConfirmMessage`で分ける)。
- **浄全DBはCORSを許可していないので`fetch`できない。** アプリ内表示はiframeで行い、
  利用者のブラウザに直接読み込ませる(こちらは本文を取得も保持もしない)。
  自前プロキシを挟む案は、相手の本文が自分たちのサーバーを経由することになるため
  採らない(`docs/tenkyo-spec.md`の大原則1)。
- 記事本文の範囲選択から逆引きへ渡す導線がある。**モバイルのOS標準の選択メニューと
  取り合いになるため、選択範囲の近くに浮かせず画面下部に固定する。**
  また押下は`click`ではなく`onPointerDown`+`preventDefault()`で拾う
  (clickを待つと、触れた時点で選択が解除されて導線自体が消える)。

## マニュアル

- 使い方は**2箇所にある**: アプリ内の `src/HelpScreen.tsx` と、リポジトリの
  `README.md` の「使い方」。**片方を直したらもう片方も直すこと。**
  マークダウンを描画する仕組みは持たせていない(そのためだけに依存を増やさない方針)。
- 挙動を変える変更(操作方法・既定値・画面の名前)を入れたら、両方の記述が
  実装と合っているか確認する。

## 記事本文の描画(落とし穴)

- 本文は`dangerouslySetInnerHTML`で流し込んでいる。**React 19はこのpropを
  オブジェクトの同一性で比較する**ため、JSXの中で`{{ __html: ... }}`を毎回作ると
  中身が同じでも`innerHTML`が無条件で書き直され、**再レンダリングのたびに本文のDOMが
  丸ごと作り替わる**。利用者の範囲選択が消え、描画後にJSで付けた印(リンク切れの
  `.broken`など)も失われる(Issue #8)。**必ず`useMemo`でpropのオブジェクトを固定すること。**
- 同じ理由で`db.getEntry()`もレンダリング本体では呼ばない(`useMemo`で`[db, currentId]`に固定)。
- `selectionchange`は選択ハンドルを動かしている間ずっと発火する。状態更新は
  `SELECTION_SETTLE_MS`で間引いてから行う。

## レイアウト

- 流動レイアウトは **1カラム⇔2カラムの二段階のみ**(タブレットは左に差定/検索、右に本文)。
- 見出し語と読みを横に並べる行(`.result-list` / `.suggestion-head`)では、
  **読みの側を`max-width`+省略記号で縮める**。読みを`flex-shrink: 0`にすると、
  読みが長い項目で見出し語が1文字ずつ折り返されて行が縦に伸びる(Issue #7)。
- 読書位置は**テキスト単位のアンカー**で保持する。回転・折り畳み開閉で位置をロストさせない。
- ヒンジ対応(Viewport Segments)は深追いしない。

## フォント

- 辞書・勤行どちらの本文にも効く**フォント選択**(Noto Serif JP=既定・Zen Old Mincho・Klee One)を
  実装済み。選択は`localStorage`(`gotou:font-choice`、`src/lib/fontChoice.ts`)に保存し、
  `:root`の`--app-font-family`をApp.tsxが書き換えることで全体に反映する。
- 3書体ともGoogle Fontsから`app/scripts/fetch-google-fonts.mjs`で取得し、
  `app/public/fonts/`に**自前ホスティング**している(オフラインファースト方針のため、
  実行時にfonts.googleapis.comへリンクしない)。取得済みのwoff2一式と
  生成された`fonts.css`は通常のリポジトリ資産としてコミット済み(大辞典由来データではない)。
- GoogleのCSSは文字のUnicode範囲ごとに数十〜百数十個の小さなwoff2に分割されており、
  自前ホスティングでもその`unicode-range`をそのまま使うため、ブラウザは実際に
  描画する文字のぶんだけ取得する(3書体×Regular/Bold合計740ファイル・約20MBだが、
  一度に全部読み込むわけではない)。
- Service Workerの変更は不要: `sw.js`の`cacheFirstRuntimeCache`(同一originのGETを
  初回ネットワーク取得→以降キャッシュ)がフォントにもそのまま効くため、
  実際に使われたサブセットは自動的にオフラインでも使えるようになる。
- スクリプトの再実行(書体追加・更新)は`npm run fetch-fonts`(手動実行専用。
  predev/prebuild/pretestには組み込まない)。

## 配布と計測

- GitHub Pages にデプロイ(Actions)。ビルド成果物に辞書データを同梱しない。
- `app/public/sw.js`の事前キャッシュ一覧(`PRECACHE_URLS`)は、`postbuild`
  (`npm run build`後に自動実行、`scripts/generate-sw-precache.mjs`)が`dist/assets/`の
  実ファイル名で機械的に補完する(`BUILD_ASSET_URLS`プレースホルダ)。ここに漏れがあると、
  SW有効化直後でまだランタイムキャッシュが無いタイミングでオフラインになった場合に
  アプリ本体が読み込めなくなる(2026-08-09に実際発生、docs/handoff.md参照)。
  ビルド成果物にファイルを追加する際はこのスクリプトが対象を拾えているか確認すること
  (フォント一式は対象外のままでよい: 欠けてもフォールバックするだけのため)。
- 計測は Plausible/Umami 系のみ。イベントはIndexedDBにキューし、オンライン時に送出。
  個人を特定するデータは収集しない。
