# 差定データモデル仕様 v0.1

勤行モードの中核データ構造。「テキスト単位=曲、差定=プレイリスト、プリセット=雛形」。

## 概念

- **テキスト単位(unit)**: 香偈・三宝礼・四奉請・懺悔偈・十念・開経偈・誦経(四誓偈など)・
  摂益文・念仏一会・総回向偈 など、差定を構成する最小のまとまり。
- **差定(saijo)**: unitの順列。地域・慣習で組み替えがあるため固定しない。
- **プリセット**: よくある差定の雛形。直接編集させず、複製→編集の動線にする。

## unitファイル (shared/gongyo/units/*.json)

```json
{
  "id": "junen",
  "title": "十念",
  "reading": "じゅうねん",
  "body": [
    { "text": "南無阿弥陀仏", "ruby": "なむあみだぶ" }
  ],
  "source": { "name": "底本名", "url": "取得元URL", "license": "PD" }
}
```

- `body` は句・段の配列。
- `ruby` は自前付与(辞書の読みインデックス資産を流用)。出版物からコピーしない。ただし
  開発者が「参照用途として使ってよい」と明示した底本がある場合は、その本文・読みと
  直接照合してよい。
- `paginated`(省略時false): trueの場合、bodyを1画面にまとめず3行ずつのバッチで
  ページ送りする(誦経・一枚起請文・長い陀羅尼など、1画面に収めると文字が小さくなり
  すぎる長文向け)。バッチの2ページ目以降は、直前ページ最終行を薄いエコーとして
  冒頭に加える(続きであることが分かるようにするため)。
- 将来: 語釈リンク(タップで辞書引き)用に、text内の収録語スパンを静的に付与する拡張を予定。

## 差定ファイル (shared/gongyo/presets/*.json およびユーザー作成分)

```json
{
  "version": 1,
  "id": "nichijo-gongyo",
  "name": "日常勤行(標準)",
  "items": [
    { "unit": "koge" },
    { "unit": "sanborai" },
    { "unit": "junen", "counter": 10 },
    { "unit": "shiseige" }
  ]
}
```

- `items` は順序付き。`counter` は十念・念仏一会のような回数表示付きunitに指定。
- ユーザーの編集操作は **並べ替え / オン・オフ / 回数指定 の3つのみ**。これ以上複雑にしない。
- ユーザー作成差定はローカル保存(localStorage)。サーバー不要。
- 共有: JSON書き出し + QRコード。僧侶が自坊の差定を檀信徒に配る経路を想定。

## 表示要件(勤行モード側への契約)

- 通常のunit(`paginated`省略時)はbody全体を1画面にまとめて表示する(グループ表示)。
  1画面に収まるよう文字サイズを段階的に縮小する。
- `paginated: true`のunitは複数行ずつバッチでページ送りする
  (2ページ目以降は前ページ最終行を薄いエコーとして冒頭に表示)。
  1タップで進む行数は1句あたりの文字数から自動決定する。
- **縦書き(既定)と横書きを切り替えられる**。経本は縦書きが基本のため既定は縦書きで、
  勤行画面のヘッダーのトグルでいつでも切り替えられる(選択はlocalStorageに保存)。
  縦書きは1行が1列を占めるため、横書きとは制約が逆転する(行数が画面の横幅を、
  1行の長さが画面の高さを圧迫する)。縦書きの字送りは端末幅に応じてCSSが
  自動的に決め(`app/src/index.css`の`.gongyo-vertical`)、1タップで進む行数だけを
  `app/src/lib/gongyo.ts`が決める。
  さらに縦書きでは、表示時にbodyを次のように組み替える(`verticalBody`):
  - **短い句(8字以下)ばかりのunitは2句ずつ全角スペースでつないで1列に収める**。
    縦書きは1列に十数文字入るため、5字の句を1句ずつ列にすると列の大半が空き、
    そのぶん列数が増えて字も小さくなる(四誓偈・摂益文等)。
  - **長すぎる句(60字超)は句読点で区切って複数ページに分ける**。1ページに
    載せようとすると字が極端に小さくなるため(一枚起請文の114字等)。
    ルビ付きの句は本文とルビの対応が崩れるので分割しない。
  **これらの調整はunitのJSONを書き換えるのではなく、必ずgongyo.ts/index.css側で行う。**
- counter付きunit(十念・三唱礼等)の**既定は簡易表示**: unit名(例「十念」)を
  ふりがな付きで1回示すだけで、1タップで次のunitへ進む(回数は数えない)。
  従来の「本文を表示しカウンターをタップで減算、0になるまで次へ進まない」方式は
  設定画面でオプトインできる(`app/src/lib/gongyoCounterMode.ts`、
  `localStorage`の`gotou:gongyo-counter-mode`)。カウンター表示時は縦書き時も
  横書きのまま表示する(縦書き文脈では数字が横倒しになるため)。
## 動的unit: 日替わり御法語 (gohogo-daily)

差定の items が `{ "unit": "gohogo-daily" }` を指していると、その日の
『元祖大師御法語』の章に置き換わる。データは `shared/gohogo/{zenpen,kohen}.json`
(作り方と権利は `shared/gohogo/README.md`)。

- **日→章**: 端末ローカルの「日」がそのまま章番号(1日=第一章)。知恩院サイト
  「今日のお言葉」と同じ規則。章は1〜31なので、**第29〜31章はその日が存在する
  月にしか登場しない**(2月は第29章まで、小の月は第30章まで)。これは仕様とする。
- **前篇/後篇**: `localStorage` の `gotou:gohogo-hen`(既定 `zenpen`)。
  設定画面で切り替える(`app/src/lib/gohogoHen.ts`)。
- **確定するタイミング**: 勤行モードをマウントしたとき(=扉が出るとき)に1回だけ
  決め、そのセッションの間は動かさない。読誦の途中で日付をまたいでも章は
  入れ替わらない。勤行モードを離れると再マウントされ、そのとき当日の章になる。
- **「続きから」で再開したときは、再開日の章で解決する。** 中断位置は
  `itemIndex` + 項目内の相対ページで持っているので(`gotou:gongyo-progress`)、
  章が変わってページ数が減っていても `resolveProgressPageIndex` が
  その項目の最後のページに寄せる。前日の章の続きを読ませることはしない。
- **unitのスキーマは広げない。** `app/src/lib/gohogo.ts` の `withDailyGohogo()` が
  当日の章を組み立てて units の表に入れるだけで、`buildPages` には手を入れていない
  (`unitsById.get(item.unit)` で引かれる側に入れておけば足りる)。解決できない
  場合はその項目だけが落ち、他の偈文は通常どおり読める。
- **勤行が使う `{ text, ruby }` はトークン列から導出する。** データは語ごとの
  対応を保っており(`shared/gohogo/README.md`)、読み物画面はそれを `<ruby>` に、
  勤行モードは句ごとのかな1行に、それぞれ落とす。
- **1句は20字以内**にしてある。御法語は全句にルビが付き、ルビ付きの行は
  `index.css` の `.gongyo-line-has-ruby` で1列に固定されている(本文とルビが
  別々に折り返すと対応が崩れるため)。折り返せない以上、1句は1列に収まる長さで
  なければ画面の下端をはみ出す。分割は表記と読みの対応を保てる factory 側で行う。
- **一文要約(`summary`)はいまアプリに表示していない。** データとしては全章に
  入っているが、僧侶の校閲が済むまで出さない(`shared/gohogo/README.md`)。

日替わり御法語版の差定は2件。中身はそれぞれ元の差定と同一で、
`ichimai-kishomon` を `gohogo-daily` に置き換えただけ:

- `nichijo-gongyo-shibujo-gohogo.json` 「日常勤行式（四奉請・日替わり御法語版）」
- `nichijo-gongyo-sanbujo-gohogo.json` 「日常勤行式（三奉請・日替わり御法語版）」

## 表示要件(続き)

- 勤行開始時は、まず差定名を表示する導入画面(扉)を挟んでから本文に入る。
  日替わり御法語を含む差定では、扉に当日の章を一行で示す
  (例「本日の御法語: 前篇第三章 聖浄二門」)。
- 差定名・現在の偈文名は常時ラベルとして表示し続ける。
- 偈文名のラベルは**必ず1行に収める**(長い名前は末尾を省略)。2行になると
  本文に使える高さが減り、`--gongyo-chrome` の見積りが足りなくなって、
  ルビ付きの句が画面の下端をはみ出す。幅が足りないときは差定名から先に詰める。
- **現在地は式次第の項目番号で示す**(例「2 / 18」)。通しのページ番号は使わない。
  18〜24項目ある日常勤行式・棚経では、通しのページ番号は「おつとめのどのあたりか」
  と対応せず役に立たないため。全体の進み具合は画面上端の細い帯で補う。
- **式次第の一覧**をヘッダーの現在地表示から開ける。項目を選ぶとその偈文の先頭へ飛ぶ。
  一覧は読誦画面に重ねるオーバーレイにする(画面を切り替えるとタブバーが出入りして
  読誦中に画面が跳ねるため)。
- **中断位置を保存する**(`localStorage`の`gotou:gongyo-progress`、
  `app/src/lib/gongyoProgress.ts`)。アプリが不意に終了しても読み手が戻れるようにする。
  - 位置は絶対ページ番号ではなく**`itemIndex` + その項目の何ページ目か**で持つ。
    ページ構成は向き・カウンターの数え方・項目のオン/オフで変わるため。
  - 復帰は**扉の「続きから」ボタン**でのみ行う。自動で途中から始めることはしない
    (再開するかどうかは必ず読み手が決める)。
  - 同じ差定の・半日以内の・先頭ではない中断位置のときだけ提案する。
    差定を選び直したとき、読み終えたときは捨てる。
