# 差定データモデル仕様 v0.1

勤行モードの中核データ構造。「テキスト単位=曲、差定=プレイリスト、プリセット=雛形」。

## 概念

- **テキスト単位(unit)**: 香偈・三宝礼・四奉請・懺悔偈・十念・開経偈・誦経(四誓偈など)・
  摂益文・念仏一会・総回向偈 など、差定を構成する最小のまとまり。
- **差定(saijo)**: unitの順列。地域・慣習で組み替えがあるため固定しない。
- **プリセット**: よくある差定の雛形。直接編集させず、複製→編集の動線にする。

## unitファイル (shared/gongyo/units/*.json)

```json
{
  "id": "junen",
  "title": "十念",
  "reading": "じゅうねん",
  "body": [
    { "text": "南無阿弥陀仏", "ruby": "なむあみだぶ" }
  ],
  "source": { "name": "底本名", "url": "取得元URL", "license": "PD" }
}
```

- `body` は句・段の配列。
- `ruby` は自前付与(辞書の読みインデックス資産を流用)。出版物からコピーしない。ただし
  開発者が「参照用途として使ってよい」と明示した底本がある場合は、その本文・読みと
  直接照合してよい。
- `paginated`(省略時false): trueの場合、bodyを1画面にまとめず3行ずつのバッチで
  ページ送りする(誦経・一枚起請文・長い陀羅尼など、1画面に収めると文字が小さくなり
  すぎる長文向け)。バッチの2ページ目以降は、直前ページ最終行を薄いエコーとして
  冒頭に加える(続きであることが分かるようにするため)。
- 将来: 語釈リンク(タップで辞書引き)用に、text内の収録語スパンを静的に付与する拡張を予定。

## 差定ファイル (shared/gongyo/presets/*.json およびユーザー作成分)

```json
{
  "version": 1,
  "id": "nichijo-gongyo",
  "name": "日常勤行(標準)",
  "items": [
    { "unit": "koge" },
    { "unit": "sanborai" },
    { "unit": "junen", "counter": 10 },
    { "unit": "shiseige" }
  ]
}
```

- `items` は順序付き。`counter` は十念・念仏一会のような回数表示付きunitに指定。
- ユーザーの編集操作は **並べ替え / オン・オフ / 回数指定 の3つのみ**。これ以上複雑にしない。
- ユーザー作成差定はローカル保存(localStorage)。サーバー不要。
- 共有: JSON書き出し + QRコード。僧侶が自坊の差定を檀信徒に配る経路を想定。

## 表示要件(勤行モード側への契約)

- 通常のunit(`paginated`省略時)はbody全体を1画面にまとめて表示する(グループ表示)。
  行数が多い場合は文字サイズを段階的に縮小する(`lineSizeTier`)。
- `paginated: true`のunitは3行ずつバッチでページ送りし、標準の文字サイズを保つ
  (2ページ目以降は前ページ最終行を薄いエコーとして冒頭に表示)。
- counter付きunitはカウンターを表示し、タップで減算する。
- 勤行開始時は、まず差定名を表示する導入画面を挟んでから本文に入る。
- 差定名・現在の偈文名は常時ラベルとして表示し続ける。
